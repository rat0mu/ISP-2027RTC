# 航電研發路徑圖

狀態：草案。依 2026-11-11 的設計進度（avbay v0.7 概念模型）擬定，尚未經團隊確認。

## 前提與假設

- 比賽（台灣盃）假設在 2027 年 8 月。實際日期確定後，請把下列月份整體平移。
- 飛行條件：目標高度約 3.4 km，不超音速，固體馬達，雙段回收。
- 航電放在鼻錐（NOSE_v1，錐體內徑 140 mm，肩部內徑 132 mm）。主傘由箭身內的商用雙重開傘高度計觸發，點火線從航電拉到箭身。
- 團隊 6 人，2 人有經驗。預算不設限，瓶頸是時間與驗證。
- 去年的堆疊（電源、通訊、主系統、備援）沒有實際飛過，沒有飛行驗證資料。去年被淘汰的原因包含審查報告不完整。
- MCU、感測器、接頭型號尚未決定，本文件不預設。

## 階段 0：需求與決策凍結（2026-11 至 12 上）

目標：把仍在漂移的設計問題先收斂。

- 寫出需求表：高度、取樣率、記錄率、續航（目前 3 小時）、遙測內容、點火輸出數量、重量與尺寸上限。
- 在 decisions.md 記錄下列決策，每項附理由與代價：
  - 堆疊構型與分層順序。
  - 中央結構件放電池，從側面取放。
  - 回收採方案 B（箭身商用高度計觸發主傘）。
  - 雙頻段遙測的分配方式（已記錄為 DEC-001：主系統 920 MHz、備援系統 433 MHz）。
- 取得台灣盃公版追蹤器（Rocket Beacon）的實際尺寸與安裝介面。目前 110×65×32 mm 是由圖估算。
- 確認比賽日期、審查報告格式與繳交期限。

開放問題（需要有人回答）：

1. 第五層是否保留？今年沒有酬載。
2. 已決定：主系統用 920 MHz，備援系統用 433 MHz，見 [DEC-001](decisions.md)。仍待確認 433 MHz 的法規與比賽規則。
3. 點火驅動電路在哪一層？主備各一組還是共用？
4. 是否裝相機？
5. 主系統與備援系統是否使用不同的 MCU 與感測器，以避免同因失效？

## 階段 1：機構定案與列印（2026-11 至 2027-01）

目標：從概念模型到可裝配的實物。

- 進度：avbay v0.8 已完成概念模型與 NOSE_v1 干涉檢查（含放大的電池槽與螺絲側蓋），尚未列印。
- 工作項：
  1. 確定列印材料與製程後，檢查壁厚、懸垂、支撐與公差。
  2. 列印中央結構件、蓋板與一組測試用 PCB 外形板（用厚紙板或廉價 PCB 即可）。
  3. 實測放入 NOSE_v1 的間隙。目前電子艙外徑 130 mm 對肩部內徑 132 mm，單邊只有 1.0 mm，要實測。
  4. 驗證電池取放、蓋板拆裝、螺桿與間隔柱組裝流程。
  5. 補完 CAD：天線同軸線路徑、固定夾、鼻錐連接與抽出機構。
  6. 以實測結果出 v1.0，並更新 docs/interfaces.md 的機構介面。
- 驗收：實體試裝件可放入鼻錐並抽出，電池可單手更換，所有螺絲可用一般工具接近。

## 階段 2：電子架構與原理圖（2026-12 至 2027-02）

目標：決定電氣介面並設計各層。

- 先決定的事：
  - MCU 與感測器選型（氣壓計、IMU 含高 g 加速度、GNSS）。感測器提案見 [DEC-002](decisions.md)，待最大加速度模擬結果確認。
  - 板間匯流排：連接器型號、腳位定義、電源與訊號分配、電壓準位。
  - 電源架構：電池組態、保護、各層電壓軌、功耗預算與 3 小時續航驗算。
  - 備援層是否完全獨立供電與獨立匯流排。
- 各層原理圖：
  - 電源層：電池保護、升降壓、分流、電流與電壓監測、開關。
  - 通訊層：920 MHz 主遙測無線電、天線介面、RF 濾波。
  - 主系統層：MCU、感測器、SD 卡、點火驅動。
  - 備援層：獨立 MCU、感測器、433 MHz 無線電、電池與記錄。
  - 主備互報序列線：心跳與摘要，含隔離或限流保護。
- 學自 HAMSTER 的設計重點：
  - 主備獨立，單點故障不得讓兩者同時失效。
  - 感測器量程可設定，並對設定錯誤報警。
  - GPS 失鎖後要能保留最後有效位置。
  - 狀態機含頂點偵測視窗與逾時保護。
- 驗收：每層原理圖由另一位成員審查並留下紀錄；匯流排與電源預算寫入 interfaces.md。

## 階段 3：開發板驗證（2026-12 至 2027-03，與階段 2 並行）

目標：在 PCB 回來之前先把軟體與演算法做完。

- 用現成開發板與感測器模組在桌上搭出最小系統。
- 韌體骨架：
  - 感測器驅動與資料記錄（SD 卡），記錄率依需求表。
  - 飛行狀態機：地面待機、助推、滑行、頂點、下降、落地。
  - 主備資料交叉檢查與簽名／序號。
  - 遙測封包格式與地面站顯示。
- 測試：
  - 主機測試：狀態機以記錄資料重播，涵蓋正常飛行、氣壓異常、加速度飽和、斷電重啟。
  - 靜態測試：壓力艙或抽真空模擬高度變化，驗證氣壓高度與頂點判定。
  - 遙測：先以開發板驗證兩個頻段各自的封包收發與地面站解析。
- 驗收：以真實或合成資料重播通過全部狀態機案例，結果有紀錄。

## 階段 4：PCB 第一版（2027-02 至 03）

- 依機構規格（馬蹄形 Ø110、4 孔 pcd 98、開口槽、連接器位置）畫外形。
- 佈局重點：
  - RF 部分的地層、阻抗控制與天線饋點。
  - 電源與類比部分的隔離。
  - 連接器同位置、同腳位，使各層可互換順序。
- 下單前：DRC、與機構外形疊圖、另一位成員逐層審查。
- 每層至少訂一組備品。

## 階段 5：板級測試（2027-03 至 04）

每層個別驗收，結果記錄在 testing.md 或專用測試紀錄。

| 層 | 主要驗證項目 |
| --- | --- |
| 電源 | 各電壓軌、負載瞬態、保護動作、電池掉電行為、3 小時續航 |
| 通訊 | 兩頻段發射功率與頻率、接收靈敏度、天線匹配與駐波比 |
| 主系統 | 感測器讀值、SD 寫入穩定度、點火輸出以假負載驗證 |
| 備援 | 獨立上電、獨立記錄、與主系統斷開時仍可運作 |

安全：點火輸出先以假負載與電流探棒測試，不接真實點火頭。

## 階段 6：堆疊整合（2027-04 至 05）

- 全部層堆疊，放入列印的中央結構件與鼻錐。
- 測試項目：
  - 板間匯流排通訊與電源在整疊下穩定運作。
  - 熱：連續運作三小時，量測最熱位置。
  - 上拉與抽出機構、電池更換、天線線路安裝的實際操作時間。
  - 920 MHz 與公版追蹤器 Meshtastic 的同頻干擾，天線距離只有約 28 mm。
  - 天線地平面與同軸線處理，比較直接裝板與延長線的射程差異。
- 驗收：完整堆疊從開機到記錄、遙測、模擬點火流程全過，並有紀錄。

## 階段 7：飛行前驗證（2027-05 至 06）

- 環境：振動、跌落、低溫與高溫、耐壓。
- 射程：地面長距離射程測試，兩頻段分別驗證，涵蓋有鼻錐遮蔽的情況。
- 系統：模擬飛行（搖動、抽氣、旋轉）觸發完整狀態機並確認動作順序。
- 點火：使用真實點火頭的安全測試，在規定安全距離與程序下進行，須另有人員在場確認。
- 放行條件寫成清單，缺一項就不放行。

## 階段 8：試飛與修正（2027-06 至 07）

- 第一次：小型驗證火箭（低風險），驗證記錄、遙測與回收訊號，不一定載完整堆疊。
- 第二次起：完整航電、真實鼻錐。
- 每次飛行後：下載資料、比對主備、記錄異常、修正後重新放行。
- 目標：至少兩次連續成功，且最後一次與比賽用版本相同。

## 階段 9：凍結與審查（2027-07 至 08）

- 凍結 CAD、PCB、韌體與設定檔，標記版本。
- 備品：每層一片、天線、電池、連接器、SD 卡。
- 完成審查報告：需求、設計理由、驗證證據、風險與對策、飛行紀錄。
- 賽前檢查清單與現場操作程序演練。

## 風險與對策

| 風險 | 影響 | 對策 |
| --- | --- | --- |
| 鼻錐間隙只有 1.0 mm | 抽不出或卡住 | 階段 1 就實測，必要時縮小外徑 |
| 920 MHz 與 Meshtastic 同頻干擾 | 遙測距離縮短 | 階段 6 實測，調整天線位置或時序 |
| 433 MHz 天線縮短到 150 mm | 效率降低 | 射程測試確認，必要時改位置或天線型式 |
| 去年堆疊沒飛過，可靠度未知 | 可能有未知失效 | 階段 7 與 8 補驗證，保留備品 |
| 審查報告不完整 | 再度被淘汰 | 從階段 0 起邊做邊寫，每階段結案時更新 |
| 公版追蹤器尺寸未知 | 艙內放不下 | 階段 0 取得實際規格 |
| 人力有限（6 人，2 人有經驗） | 進度落後 | 並行階段 2 與 3，經驗成員分攤審查 |
