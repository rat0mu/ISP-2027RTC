# 首次工作清單

以下是可依序建立的 Issue 範例，尚未指派人員，也沒有自動建立 GitHub Issue。

| 順序 | 任務 | 交付物 | 驗收 |
| --- | --- | --- | --- |
| 1 | 確認 repo 與分工 | team.md 更新、協作者權限 | 另一位成員能 clone、開分支與 PR |
| 2 | 演練文件任務 | 一個小型文件 PR | 另一人審查，文件檢查成功並合併 |
| 3 | 確認目錄與共用規則 | 各模組 README 的必要修正 | 常見檔案都有一致放置方式 |
| 4 | 提出系統架構草案 | architecture.md 與討論紀錄 | 職責、待決問題與負責人明確 |
| 5 | 定義第一批跨模組介面 | interfaces.md 更新 | 提供方與使用方共同確認 |
| 6 | 確認工具與首個實作入口 | 工具版本、最小可重現流程 | 第二位成員可依文件操作 |

每個任務使用 [Task 模板](../.github/ISSUE_TEMPLATE/task.md)，填入目的、範圍、交付物、驗收條件、執行者與審查人。

先完成可檢查的小成果；新增實作後再規劃對應測試與里程碑。
