# 維護者指南

本文件提供操作與說明；協作要求以 [CONTRIBUTING.md](../CONTRIBUTING.md) 為準。

## GitHub 設定與團隊分工

### 需要維護者在 GitHub 設定的項目

| 項目 | 初期建議 |
| --- | --- |
| 協作者 | 依職責設定適當權限，確認每人可正常操作 |
| main 保護 | 初始化後要求 PR；審查人到位後要求至少一位其他成員核准 |
| 歷史保護 | 限制 main 的 force push 與刪除，明確安排例外處理 |
| 自動檢查 | 先建立可信檢查，再加入必要 status check |
| CODEOWNERS | 填入有權限的真實帳號並改名後才啟用 |
| 備援維護者 | 至少安排另一位能維護 repo 的成員 |

可用設定依 GitHub 帳號方案、repo 類型與權限確認。推送模板不會自動建立保護規則、協作者、labels 或 Project。已附文件 CI，執行仍受 repo 的 Actions 設定影響，見 [自動檢查](automation.md)。

### 責任安排

目前負責人尚未指定，請更新 [團隊分工](team.md)。

- **Repo 維護者**：管理權限、流程、整合與發布。
- **模組負責人**：維護介面、協調方向與確認整合。
- **任務執行者**：推進工作並提交成果與證據。
- **審查人**：依驗收條件檢查，提出問題與確認結果。

角色可以依人力兼任，但重要變更仍由另一位成員檢查。讓審查能力分散到各模組，減少所有工作都必須等待單一組長。


## 初始化完成清單

以下清單在團隊確認完成後再勾選，不代表模板已替你操作 GitHub。

- [ ] 確認 repo 名稱與 Public／Private。
- [ ] 指定主要與備援維護者。
- [ ] 團隊閱讀並確認採用協作規範。
- [x] 建立 GitHub repo 與初始提交。
- [ ] 邀請協作者並確認權限。
- [ ] 填入初期分工與審查安排。
- [ ] 在 GitHub 設定適用的 main 保護。
- [ ] 由另一位成員完成一次 clone、分支、commit、push、PR 與合併演練。
- [ ] 根據演練修正操作說明。
- [ ] 後續有實作時更新架構、介面、工具與驗證資訊。

目前優先讓成員知道檔案位置、任務入口、提交方式與審查責任。硬體細節、建置、自動測試與正式發布制度隨實際成果逐步建立。
